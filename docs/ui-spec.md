# UI 規格 — 四個頁面

整體:頂部 Nav Bar(Logo「小勞鼠」+ 四個頁籤),白底深藍主色,正式企業風。

## 1. 智能問答(/chat)— Demo 主畫面,優先做到最好
版面:左側窄欄(情境入口)+ 中間對話區 + 右上身分切換

- 身分切換:右上角 toggle「資方 / HR」⇄「勞工」,切換時:
  - 範例問題 chips 跟著換
  - 對話區頂部顯示目前身分的 badge
- 情境入口:左欄三張小卡(職災處置 / 資遣爭議 / 法規雷達),點選後載入該情境的範例問題
- 範例問題 chips:對話區上方 2-3 顆,點擊直接送出
- 對話氣泡:
  - AI 回答用 react-markdown 渲染(支援表格、清單)
  - ```mermaid 區塊渲染成圖
  - 右上角「複製」按鈕(複製原始 Markdown,成功後短暫顯示「已複製」)
- 法條卡片:回答中偵測到法條引用(或 mock 資料中標記),在回答下方以卡片呈現:
  法條編號 + 一句摘要,點擊展開條文
- 文件清單:解析回答尾部的「參考來源」標註段渲染成 chips,僅顯示名稱不可點開原文;若該次回答沒有標註段,此區塊隱藏。
- 「查看推理路徑」按鈕:回答下方,點擊跳轉知識圖譜頁並帶入該次問答的路徑
- 推理路徑資料來自最終 chunk 的 cyphers,不依賴其他 API;若 cyphers 為空陣列(純 vector 回答),按鈕隱藏。
- 串流:逐字渲染,等待時打字中動畫(三個點)

## 2. 案件調查(/investigate)— 諮詢員親自建議的功能
版面:左側步驟條 + 主表單區

- Step 1:選情境類型(三張大卡)
- Step 2:填參數(欄位見 scenarios.md,表單元件要有清楚 label 與提示)
- Step 3:生成報告(loading 時顯示「AI 正在分析案件...」)
- 報告頁面區塊(由上到下):
  1. 案件摘要(把填入參數整理成一段)
  2. 法定義務 SOP — 垂直時間軸元件,每步含期限 badge(如「8 小時內」)
  3. 應備文件清單 — checklist 樣式
  4. 風險評估 — 紅黃綠燈或風險等級 badge
  5. 相似歷史案例 — 卡片列表
- 報告底部:「下載 PDF」「存為報告」按鈕(存為報告 → 寫入風險報告頁的列表)
- 下載 PDF 可用瀏覽器列印樣式(print CSS)實作即可

## 3. 風險報告(/reports)
- 報告列表:卡片(標題 + 情境類型 tag + 日期 + 風險等級)
- 點擊進入報告詳情(同案件調查的報告版面)
- MOCK 模式預塞 2-3 筆漂亮的歷史報告(demo 時看起來像被使用過的系統)

## 4. 知識圖譜(/graph)
- 目的:讓評審「看見」GraphRAG 的推理過程,重質不重量
- 顯示單次問答的推理路徑:5-10 個節點的清晰路徑,不是整張圖
- 節點分類上色:案件(藍)/ 法條(綠)/ 公司(橘)/ 裁罰(紅),圖例放角落
- 路徑上的節點與邊高亮,其餘淡化
- 點擊節點顯示屬性面板(右側抽屜)
- 頂部顯示觸發這條路徑的問題文字
- MOCK 資料:為三個情境各準備一條路徑(例:問題 → 相似案件節點 → 違反法條節點 → 裁罰金額節點)

## 共用
- 空狀態、錯誤狀態都要設計(API 失敗顯示重試)
- RWD 不強求,以 1920x1080 投影與錄影為主
