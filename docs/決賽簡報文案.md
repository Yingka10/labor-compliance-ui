## P4 ｜問題定義：勞動合規是最貴的隱形風險（章節③Problem）

**主標**：一步沒做對，就是罰鍰，甚至刑責

用我們自己的資料集當錨點（真實、站得住）：

- **資訊服務業累計 3,340 件勞動法裁罰**（本系統資料集），最大宗是**工時/加班 1,187 件（35.5%）**——正是過勞的溫床。
- 勞動法規分散 **26 部**，職災通報、資遣預告都有**法定期限**，漏一步就觸法。
- 一般 AI 助理（如 ChatGPT）**會杜撰條號**——但法律場景不能錯。

三個痛點框（比照得獎隊的六邊形/色塊並排）：

| ① 法規分散、時限緊 | ② 罰則重、可至刑責 | ③ 勞資資訊不對稱 |
|---|---|---|
| 26 部法規、各種通報期限 | 漏報/逾期即裁罰 | 勞工不知能主張什麼、找誰 |

口播（約 35 秒）：
「光是資訊服務業，我們的資料庫就收錄了 3,340 件勞動法裁罰，最大宗是工時加班、一類就 1,187 件，正是過勞的溫床。對 HR 來說，職災、資遣都有法定通報期限，漏一步就是罰鍰甚至刑責；對勞工來說，根本不知道自己能主張什麼、該找哪個窗口。而你問一般 AI，它還會把法條編錯。這就是我們要解的問題。」

對應評分：應用情境與商業價值 20%。

## P9 ｜技術與應用架構圖（章節④System｜決賽必交：證明可上市）

**主標**：從知識庫到使用者，一條打通的技術與應用架構

> 對應決賽額外要求：「最終技術與應用之架構圖，證明產品已具備進入市場的成熟度」＋ 技術深度的「API 串接」。重點是讓評審看到 **Hybrid RAG Chat API 真的串進了我們的應用**。

架構圖（四層，左到右一條流）：

```
[ 知識庫層 ]            [ EAP 推理層 ]              [ 介接層 ]          [ 應用層 ]            使用者
GraphRAG 圖譜      →   Hybrid RAG（Vector＋Graph） →  Chat API     →  小勞鼠 Web         →  HR
VectorRAG 26 PDF        ＋ AI Agent                   （已實際串接）   問答／調查／摘要 三頁    勞工
裁罰風險資料            ・情境路由（職災/資遣/雷達）                    ＋ 身分視角注入
                        ・身分視角 ・引用紀律
                                └─────  逐字串流（SSE）回傳  ─────┘
```

四層各一句（圖下小字）：
- **知識庫層**：上一頁煉好的圖譜＋26 部 PDF＋裁罰資料。
- **EAP 推理層**：Hybrid RAG 同時跑 Vector 與 Graph；**AI Agent** 負責情境路由（職災／資遣／雷達）、身分視角與引用紀律。
- **介接層**：透過 EAP 的 **Hybrid RAG Chat API** 串接——這是「已實作、可上市」的證據（Demo 影片可見真實 API 往返）。
- **應用層**：小勞鼠三頁 Web，回答逐字串流回前端、法條連官方原文。

口播（約 30 秒）：
「這是我們實際設計、實際跑起來的架構。最左邊是上一頁煉好的知識庫；送進 EAP 的 Hybrid RAG，由一個 **AI Agent** 判斷情境、套上身分視角、管好引用紀律；再透過 EAP 的 **Chat API 串進我們自己的小勞鼠 Web**——這條 API 是真的接通的，等下 Demo 影片就看得到真實往返。從知識庫到使用者，整條鏈都實作完成，不是概念圖。」

> 備註：介接層即自建的輕量中介層（Proxy）；CORS、隱藏 token 這些是水電、不上台講，版面只留「Chat API 已串接 ＋ 身分視角／圖譜路由注入」這兩個有鑑別度的點。

對應評分：技術應用深度 20%（API 串接）＋ 整合創新 15% ＋ 決賽必交架構圖。

## P10 ｜三頁串接工作流（章節④System / ⑤介面）

> 順序：工作流在 P10（先把「問答→報告→摘要」這條管路建起來），身分分流在 P11（再叉出兩種視角）。

**主標**：從一句提問，到一份可歸檔文件

流程（三頁串接）：

```
智能問答  ──立案調查──▶  案件調查報告  ──匯出──▶  諮詢摘要（下載 Word / PDF）
```

案件調查報告不是空泛 AI 回答，而是規則引擎算出來的：
- **法定義務時間軸**：依錨點日期推算各義務期限，標「法定期限 vs 建議時程」，逾期紅燈、可勾選
- **資遣費 / 預告期試算**：勞退新制（0.5 月/年、上限 6 月）與舊制、預告 10/20/30 日
- **風險定價**：聚合 IT 裁罰資料（3,340 件），給件數 / 罰鍰中位數 / 最高額 / 代表案例（無真實資料時誠實標示、不造假）
- **應備文件清單**：可勾選，每項標「法定 / 建議」

版面：Demo 會 live 走這條流程，slide **不放大張截圖**——一條流程箭頭概念圖 + 三張小縮圖（問答 / 報告 / 摘要），報告縮圖看得到「時間軸 + 風險定價」即可，讓靜態 deck 也讀得到。

口播（約 30 秒）：
「我們不只做問答。一句提問可以一鍵立案，生成結構化的調查報告——裡面的義務時間軸、資遣費試算、風險定價，都是規則引擎依法條算出來的，不是模型隨口說。最後還能匯出成 Word 或 PDF 帶走。這是一個完整的 HR 工作流閉環。」

對應評分：應用情境 20% + 介面設計 15%。

## P11 ｜身分分流 ★（章節④System，最獨特創意）

## P12 ｜Vibe Coding：用自然語言駕馭圖譜與視角（章節④System）

**主標**：用自然語言，駕馭圖譜、視角與引用紀律

- **真實 prompt 範例**（節錄，放程式碼框）：

## P13 ｜可驗證 · 不唬人（章節④System，防幻覺）

**主標**：法律 AI 最怕唬人——所以每句話都能當場核對

法遵產品最大的疑慮就是 AI 幻覺。我們的做法是讓每一句都附上可即時驗證的出處：

- **法條點得開官方原文**：每條引用都連到「全國法規資料庫」的**單條深連結**（直接跳第 N 條，不是整部法規），26 部勞動法規逐一查證。
- **法定 vs 建議，分得清楚**：義務時間軸、應備文件逐項標「法定 / 建議」，不把實務建議冒充法律義務；時效有爭議（如資遣費）就**如實列出勞動部與法院兩種見解**，不假裝有標準答案。
- **風險數字只用真資料**：裁罰定價只聚合 API 回傳的真實案例，查無資料時誠實標示「本次未取得相似裁罰案例」，絕不編造數字。

一句點題（大字）：**別的法遵 AI 給你一段「看起來合理」的文字；小勞鼠給你可以當場驗證的研判。**

口播（約 30 秒）：
「法律場景最怕 AI 唬人。我們的做法是讓每一句都能被核對：每條法條都點得開全國法規資料庫的官方原文，而且直接跳到第幾條；我們還分清楚什麼是法定義務、什麼只是實務建議——像資遣費時效有爭議，我們就誠實列出勞動部和法院兩種見解；風險數字也只用真實裁罰資料，查不到就說查不到、絕不編。待會的 demo，歡迎評審當場點任一條法條，跳到官方原文核對。」

對應評分：技術應用深度 20% + 整合創新能力 15%（可信度）。
